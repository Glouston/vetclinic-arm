# АРМ диспетчера ветеринарной клиники

Курсовой проект по проектированию баз данных. Десктопное приложение: **Python 3.9+ · SQLite · PySide6**.

## Установка и запуск

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -U pip           # на 3.9 системный pip слишком старый для колёс PySide6
pip install -r requirements.txt
python -m app.main
```

При первом запуске, если файла БД ещё нет (или он пуст), приложение само создаёт `vetclinic.db`
из `schema.sql` и `seed.sql`. **Существующая БД никогда не очищается.** Путь к БД можно задать переменной
`VETCLINIC_DB=/путь/к/файлу.db`.

### Ручное развёртывание из скриптов (порядок важен)

```bash
sqlite3 vetclinic.db < schema.sql    # 1. схема: таблицы, индексы, триггеры, представления
sqlite3 vetclinic.db < seed.sql      # 2. тестовые данные
```

Восстановление демонстрационных данных: удалить `vetclinic.db` и запустить приложение (или повторить команды выше).

### Дата и тестовые данные
`seed.sql` рассчитан на «сегодня» = **2026-10-28**. Если системная дата другая, дашборд и просрочки будут отличаться.
Варианты: `VETCLINIC_TODAY=2026-10-28 python -m app.main` или перегенерировать данные под текущую дату:
`python tools/gen_seed.py --today $(date +%F) > seed.sql`.

### Обновление существующей БД
Если `vetclinic.db` создан прежней версией (платежи были привязаны к `visit_id`), при запуске приложение само
обновит таблицу `payments` до новой схемы (`appointment_id`, предоплата) **без потери данных**; перед этим рядом
сохраняется копия `vetclinic.db.bak-before-prepay`. Строгие проверки дат (`date(x) = x`) действуют для БД,
развёрнутых из нового `schema.sql`.

### Оплата
Оплатить запись можно в любой момент: сразу при записи (полностью или частично — предоплата) или в день приёма.
При закрытии приёма «ожидает» начисляется только на неоплаченный остаток; при отмене записи внесённая сумма
автоматически оформляется возвратом. Счёт (PDF) печатается по записи в разделе «Записи на приём».

### macOS: «Python неожиданно завершил работу» при запуске
Если `.venv` лежит в `~/Documents`, macOS может пометить файлы внутри папок с точкой флагом *hidden*; Qt тогда
не видит свой плагин платформы и падает. Приложение снимает этот флаг с плагинов Qt само при старте
(`app/qt_env.py`); вручную: `chflags -R nohidden .venv`. В PyCharm используйте интерпретатор `vetclinic/.venv`
(Python 3.13) либо, для Python 3.9, `reportlab<5` (версия 5 требует Python 3.10+).

## Структура

| Путь | Назначение |
|---|---|
| `schema.sql`, `seed.sql`, `queries.sql` | схема БД, тестовые данные, 16 содержательных запросов Q01–Q16 |
| `app/db.py` | подключение (`PRAGMA foreign_keys=ON`), транзакции `BEGIN IMMEDIATE` |
| `app/repositories/` | весь SQL (только параметризованный), без бизнес-логики |
| `app/services/` | бизнес-правила: запись, закрытие приёма (FIFO-списание), оплаты, склад, напоминания |
| `app/reports/` | три отчёта (SQL), выгрузка XLSX, печатные формы PDF |
| `app/ui/` | PySide6: страницы, диалоги, модели `QAbstractTableModel`, QSS-тема. SQL в виджетах отсутствует |
| `tests/` | pytest: ограничения БД, транзакции, отчёты, smoke-тесты UI (pytest-qt) |
| `tools/` | генератор seed, проверка запросов + EXPLAIN, генератор словаря данных |
| `docs/` | материалы пояснительной записки: словарь данных, ER, нормализация, правила, сценарии |

## Тесты

```bash
pytest -v                         # все тесты (UI — offscreen)
python tools/check_queries.py     # выполнить queries.sql + EXPLAIN QUERY PLAN
```

## Горячие клавиши
Ctrl+N — новая запись · Ctrl+F — поиск · F5 — обновить · Ctrl+P — печать · Esc — закрыть диалог.

## Журнал
Технические подробности ошибок пишутся в `logs/vetclinic.log`; пользователю показываются только понятные сообщения.
